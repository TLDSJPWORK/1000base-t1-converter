# 0009: 1台目をmaster、2台目をslaveにする

- 日付: 2026-09-13
- 状態: 採用（ユーザーが2台接続後の作業継続を依頼）

## 確認結果

両ボードのジャンパ由来の設定はslaveだった。SOR_VECTOR_1=0x1108のbit5が0、
PMA MMD1:0x834=0x8001で一致した。ソフトからmasterへ変更できることを実機で確認し、
両側のT1リンクがupになった。

## 決定と理由

1台目（USB固有番号E6658C344B929F2A）をmaster、2台目
（E6658C344B28AB2B）をslaveにする。既に記録された番号と基板番号の対応を維持し、
作業中の対象を追跡しやすくするため、1台目を変更側に選んだ。

PMA制御はMMD 1内のアドレス0x834へ0xC001（master）または0x8001（slave）を
設定し、変更時はClause 22 register 0x1Fへ0x4000を書いてソフト再起動する。
TI資料の0x1834はMMD番号1と内部アドレス0x834を結合した表記として扱う。

## 永続化方法

同じバイナリへ基板固有設定を保存せず、master用とslave用のUF2を生成する。
成果物名から役割を判別でき、ジャンパを変更しなくても電源投入時に役割を再適用できる。
既定のdiagnosticビルドは役割を変更しない。

## 影響

master/slave設定はPHYレジスタへの上書きであり、SOR_VECTORのジャンパ読取値は変わらない。
T1リンク成立は確認済み。RGMIIとRJ45側のリンク、PC–Raspberry Pi間の転送は別途確認する。

## 実施結果

役割別0.2.0を両台へ書き込み、Flash照合に成功した。電源投入時の自動設定は
1台目0xC001、2台目0x8001として読み戻され、両側のT1リンクがupになった。
この結果により、ジャンパが両方slaveでもソフトウェア上書きで対向リンクを維持できることを確認した。

参考: TI DP83TG720R-Q1 data sheet、TI DP83TC81x/DP83TG72x Software Implementation Guide。
